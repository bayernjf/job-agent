# 走查：第一次来的陌生访客，在产品里会卡在哪

- 日期：2026-10-08　|　走查人：agent（零上下文视角）　|　对象：**生产** `https://app.job-agent.bayjf.com`（只读，未触发任何新分析）
- 方法：入口页 → 示例报告页（匿名）逐屏看渲染结果与可点面；文案与数据同时回查代码与 API 返回值，不把"看起来像缺陷"当结论。
- 状态标记：✅ 本轮已修　🔧 待修（有明确做法）　❓ 待你拍板　⬜ 本轮没能测到

## 1. 结论先说

产品**能走完**，但**首屏不告诉你是谁、给谁用、下一步做什么**。三处最伤：主操作位被「申请移除此画像」占据；入口对"要等多久"零预期（本轮已修）；示例预设给陌生人的第一印象是两个负面结论。而最关键的一条我**测不到**——新用户注册→认领→第一次拿到报告，需要真实 GitHub 授权（见 §5）。

## 2. 逐条发现

| # | 发现 | 证据 | 状态 |
| --- | --- | --- | --- |
| 1 | 提交前没有任何等待说明，用户点「生成画像」后只看到"正在分析，请稍候…" | `AnalyzeForm` 提交前只渲染 `home.placeholder/analyze`；队列真相（`job.stillQueued.*`）要等 5 分钟轮询预算耗尽才出现 | ✅ 新增 `home.waitHint`（中英同构），提交前就显示；已按 SSR 实测两语种都渲染 |
| 2 | 排队文案停在"计划每小时一次"——决策 #24（2026-10-06）之后已过期 | 生产实测 Worker cron 为 `*/5`（两次触发 10:05:29Z / 10:10:29Z 均 `Ok`）；GH 侧 `*/15` 实测只交付 ~4.5% | ✅ 改为"每 5 分钟一次的定时任务（2026-10-06 起；此前每小时…）"，保留"超过一天无进展＝通道故障"的诚实兜底 |
| 3 | 顶部导航把两个受众并列：`首页 / 我的 / 求职工作台 / 筛选人才`，陌生人无法判断"这是给我用的还是给 HR 用的"；且「筛选人才」点进去是声明墙 | 生产 `/zh-CN/recruit` 匿名返回的是"声明招聘方"卡片（实测 HTML 含 `declareConfirm` 文案） | ❓ 建议：未登录默认只给 C 端三项，招聘入口降到页脚；或导航按身份态收敛 |
| 4 | 三条示例预设里有一条是运营者本人账号（`bayernjf`，标签"信号混合"），另一条"证据不足"——**陌生人第一眼看到的三个样本，两个是负面结论**，且没有任何一处解释"信号混合"是什么 | `/api/demo/presets` 三条；入口页截图核对 | 🔧 预设文案加一句解释 + 考虑换掉本人账号那条（换成结论更正面的公开样本） |
| 5 | **首屏第一个按钮是「申请移除此画像」**，合规入口占了主操作位；对刚生成自己画像的人是强烈错信号 | 报告页 DOM 顺序：`btns[0]="申请移除此画像"`，其后才是徽标与招聘方视角 | 🔧 未认领/非本人时降为页脚文字链；本人认领后才回到操作区 |
| 6 | 报告页 10 个区块并列、10 个一模一样的「针对此岗生成简历」，**没有"下一步"**（简历生成之后去哪？投递？扩展？） | 报告页 `h2` 十项 + 按钮去重后只剩一种 CTA | 🔧 概述下方加一条"接下来"引导（画像→简历→投递→回标），按当前身份态显示可做的那一步 |
| 7 | Chrome 扩展（"一键填充 ATS"）在入口页**完全不可见**——这是与 DINQ 拉开差距的能力，却藏在装完才看得见的地方 | 入口页无扩展相关文案/链接 | 🔧 入口页与报告页简历区块各加一条安装引导 |
| 8 | 匿名访客可以在**别人的（未认领）画像**上看到「+ 新增投递」并写入 | 报告页匿名 DOM 有 `+ 新增投递`；`/applications` 对未认领画像公开读写是 2026-09-25 的既定口径；设计文档 §1.2 已把"投递记录任何人都能写"列为"今天就能打穿的故障面"，至今未修 | ❓ 产品级风险：任何人可向他人画像注入投递记录，而 `/my`、投递追踪会当真数据展示。要不要收紧成"仅本人可写"，是决策，不是 bug |
| 9 | 信号行右侧打印内部码（`r0.1.sig.author_inconsistency` 等） | 报告页实测文本 | ❓ 对招聘方是可审计性的证据，对陌生人是噪音——保留但挪到次级字号/悬浮提示？ |
| 10 | 我一度怀疑「C 开发者」是等级码泄漏 | 回查数据：`headline="C developer with 28 public repos…"`，主力语言标签就是 **C 语言**；`seniorityHint` 的取值域是 `senior/mid/junior`，`composeSeniorityBand('senior','zh-CN')='资深'` | ✅ 怀疑撤回（渲染正确）。留一条文案建议：zh 下写「C 语言开发者」更不易误读 |
| 11 | 我上一轮说"J6 异议邮箱没配"，依据是首页没有 mailto | 报告页实测**有** `mailto:dispute@job-agent.bayjf.com`（首页本就不该有） | ✅ 推断撤回。**未知**：这个邮箱是否真有收件箱，我无法验证 |

## 4. 给真人试用的一页脚本（你转发用）

> 目标：看**谁在第几步停下来**。请不要客气，把原话贴回来。
>
> 1. 打开 `https://app.job-agent.bayjf.com/zh-CN/`（或 `/en/`）。**不要登录。** 输入你自己的 GitHub 用户名，点「生成画像」。→ 记录：你预期要等多久？页面上哪句话给你的预期？
> 2. 等结果期间关掉页面，5 分钟后回来，从「我的」进去找它。→ 记录：找得到吗？
> 3. 报告出来后，从上往下滑一遍。→ 记录：哪一块你最想看？哪一块你看不懂？
> 4. 挑一个推荐岗位点「针对此岗生成简历」，把下载的 `.md` 打开。→ 记录：有没有一句让你想改的话？
> 5. 点「以招聘方视角查看（核验证据）」。→ 记录：如果这是 HR 看你，你会不会不服？不服哪一条？
> 6. 用 GitHub 登录，认领这个画像。→ 记录：卡在哪一步？
> 7. 在「投递追踪」里加一条你真实的投递，并在结果列标一次。→ 记录：这个字段你觉得有用吗？
> 8. 最后只答一句：**你会把这个链接发给谁？**
>
> 回收格式（每人 4 行以内即可）：`第几步卡住 / 原话一句 / 是否登录成功 / 会不会转发`。

## 5. 本轮**没能**测到的（最重要的一节）

- **新用户注册→认领→第一次拿到报告**这条主路我走不了：需要真实 GitHub OAuth 授权，只有你的账号可点。**这条恰恰是最可能藏断点的路。** 两个解法：① 你按 §4 自己走一遍第 6 步并贴回原话；② 给我一个可弃用的测试 GitHub 账号（或允许我用你的账号只走认领）。
- **手机视口与响应式**：in-app 浏览器的截图面本次不可用（只能取 DOM/SSR 文本），视口切换也不可用。移动端布局至今**没有任何自动化或人工验证**。
- **登录后的工作台/投递回标/BYOK 面板**：真全栈 E2E 覆盖（`pnpm e2e:agent`），但那是夹具账号，不是"一个真人第一次打开"。
- `dispute@job-agent.bayjf.com` 是否有人收信，未验证。
