# 走查：第一次来的陌生访客，在产品里会卡在哪

- 日期：2026-10-08　|　走查人：agent（零上下文视角）　|　对象：**生产** `https://app.job-agent.bayjf.com`（只读，未触发任何新分析）
- 方法：入口页 → 示例报告页（匿名）逐屏看渲染结果与可点面；文案与数据同时回查代码与 API 返回值，不把"看起来像缺陷"当结论。
- 状态标记：✅ 本轮已修　🔧 待修（有明确做法）　❓ 待你拍板　⬜ 本轮没能测到

## 1. 结论先说

产品**能走完**，但**首屏不告诉你是谁、给谁用、下一步做什么**。三处最伤：主操作位被「申请移除此画像」占据；入口对"要等多久"零预期（本轮已修）；示例预设给陌生人的第一印象是两个负面结论。而最关键的一条我**测不到**——新用户注册→认领→第一次拿到报告，需要真实 GitHub 授权（见 §5）。

## 4. 给真人试用的一页脚本（你转发用）

> 目标：看**谁在第几步停下来**。请不要客气，把原话贴回来。
>
> 1. 打开 `https://app.job-agent.bayjf.com/zh-CN/`（或 `/en/`）。**不要登录。** 输入你自己的 GitHub 用户名，点「生成画像」。→ 记录：你预期要等多久？页面上哪句话给你的预期？
> 2. 等结果期间关掉页面，5 分钟后回来，从「我的」进去找它。→ 记录：找得到吗？
> 3. 报告出来后，从上往下滑一遍。→ 记录：哪一块你最想看？哪一块你看不懂？
> 4. 挑一个推荐岗位点「针对此岗生成简历」，把下载的 `.md` 打开。→ 记录：有没有一句让你想改的话？
> 5. 点「以招聘方视角查看（核验证据）」。→ 记录：如果这是 HR 看你，你会不会不服？不服哪一条？
> 6. 用 GitHub 登录，认领这个画像。→ 记录：卡在哪一步？
> 7. 在「投递追踪」里加一条你真实的投递，并在结果列标一次。→ 记录：这个字段你觉得有用吗？
> 8. 最后只答一句：**你会把这个链接发给谁？**
>
> 回收格式（每人 4 行以内即可）：`第几步卡住 / 原话一句 / 是否登录成功 / 会不会转发`。

> **2026-10-08 第二轮补充**：首页新增 `home.visitorHint`（未登录访客说明"无需注册可看公开画像，登录认领后可管理/简历/投递"），报告页新增 journey 引导——但 §5 的真人路径（注册→认领→首报）依然需要你走一遍 §4 第 6 步，手机视口依然零验证。

## 5. 本轮**没能**测到的（最重要的一节）

- **新用户注册→认领→第一次拿到报告**这条主路我走不了：需要真实 GitHub OAuth 授权，只有你的账号可点。**这条恰恰是最可能藏断点的路。** 两个解法：① 你按 §4 自己走一遍第 6 步并贴回原话；② 给我一个可弃用的测试 GitHub 账号（或允许我用你的账号只走认领）。
- **手机视口与响应式**：in-app 浏览器的截图面本次不可用（只能取 DOM/SSR 文本），视口切换也不可用。移动端布局至今**没有任何自动化或人工验证**。
- **登录后的工作台/投递回标/BYOK 面板**：真全栈 E2E 覆盖（`pnpm e2e:agent`），但那是夹具账号，不是"一个真人第一次打开"。
- `dispute@job-agent.bayjf.com` 是否有人收信，未验证。
