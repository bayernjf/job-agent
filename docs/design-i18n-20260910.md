# JobAgent i18n 设计（自研轻量 `t()` + JSON 字典）

> 状态：**现行**；日期：2026-09-10（2026-09-14 增补第 8 节，覆盖浏览器扩展）；适用范围：**本仓库 `job-agent` 全部用户可见界面——报告页 `apps/report` 与浏览器扩展 `apps/extension`**。
> 依据：决策 #4 修订为「海内外同步」（[待拍板决策清单 #4](待拍板决策清单-20260910.md)）、[PRD NFR-8](PRD.md)、[AGENTS.md i18n 硬约束](../AGENTS.md)。
> 方案已定（2026-09-10）：**自研轻量 `t()` + 中英 JSON 字典 + key 对齐一致性测试，不引入 i18n 框架**。

## 1. 目标与非目标

**目标**

1. 报告页与所有用户可见界面 P0 即中英双语，两语言**同等质量**，不做「中文为主、英文凑合」。
2. 新增文案的成本趋近于零：写组件时只认 `t()`，不存在「忘了翻译」的路径。
3. 中英 key 对齐由**编译期类型 + 单测**双重守护，而不是靠 review 发现漏翻。

**非目标（本期明确不做）**

- **落地页 `job-agent-landing`（独立仓库）不在本文档范围**，由项目负责人自行推进；本仓不复制其实现、不替它做决定。
- 不做第三语言、不做 RTL、不做运行时在线翻译/机翻管线（见 [deferred-items.md](deferred-items.md)）。
- 不把 GitHub 原始内容（commit message、仓库名、Issue 标题等）翻译成中文——证据必须保持原样可回溯。
- CLI 输出属开发者内部工具，不强制双语（保持英文即可）。

## 2. 目录与文件

报告页落地（M1·W4）时在 `apps/report` 建立：

```text
apps/report/src/i18n/
├─ messages/
│  ├─ zh-CN.json      # 单一事实源：key 先在这里加
│  └─ en.json         # 同构英文副本
├─ index.ts           # t() / createTranslator() / 类型导出
└─ i18n.test.ts       # 中英 key 对齐 + 空值 + 占位符一致性
```

- 语言集合：`zh-CN`、`en`（**内部标识用英文**，展示名也进字典）。
- 字典文件是 `.json`，由 `index.ts` 静态 import，保证类型可推导、构建期可校验。

## 3. 契约

```ts
export const locales = ['zh-CN', 'en'] as const;
export type Locale = (typeof locales)[number];
export type MessageKey = keyof typeof zhCN;          // 唯一事实源推导

export const en: Record<MessageKey, string>;         // 缺 key 直接编译报错
export function translate(locale: Locale, key: MessageKey, params?: Record<string, string | number>): string;
export function createTranslator(locale: Locale): (key: MessageKey, params?: ...) => string;  // 组件里用 t()
```

- **插值**用 `{name}` 占位符，`t(locale, 'profile.summary', { count: 12 })`；不做复数规则（P0 用「条/items」等中性写法或数量外置），复数形态成为刚需时再评估引库（见 deferred）。
- **key 命名**：`<模块>.<对象>.<语义>`，全小写点分，如 `report.authenticity.likelyAuthentic`、`report.evidence.viewOnGithub`；禁止用中文或整句英文原文当 key。
- **新增流程（硬约束）**：先加中文 key + 中文文案，立即补同构英文 key，二者同一次提交完成。

## 4. 语言选择与分享链接

- 默认语言按 `Accept-Language` 协商，协商失败回落 `en`（海外优先不至于落到中文）。
- 报告页 URL 带语言段（`/zh-CN/...` 与 `/en/...`）或 `?lang=`；**分享链接显式携带语言并一旦生成即固定**，避免同一链接在不同浏览器呈现不同语言造成结论误解（与「画像快照」同原则）。
- 语言切换器只切换当前 URL 的语言段，不丢失报告定位。
- 语言切换器本身的文案（如「English / 中文」）是 AGENTS 允许的硬编码豁免项。

## 5. 术语与「不翻译」边界

| 类别 | 处理 | 例子 |
| --- | --- | --- |
| 产品术语（真实性分级等） | 枚举值保持英文，展示层映射字典 | `likely_authentic` → 「可信度较高」/ "Likely authentic" |
| GitHub 原始内容 | **原样展示，不翻译** | commit message、repo 名、Issue 标题 |
| 代码标识符 / 内部 ID | 不翻译 | `analysis_jobs`、`ep-xxx` |
| 数字、日期、相对时间 | 走 `Intl` 按 locale 格式化，不手写拼接 | `2026-09-10` / "Sep 10, 2026" |
| 法律与合规文案 | 中英各自表述，不做逐字对照（法域不同） | 隐私说明、异议入口 |

## 6. 验收标准

1. `apps/report` 源码中**无硬编码用户可见字符串**（白名单：代码注释、术语数据、placeholder 示例、语言切换器）。
2. `i18n.test.ts` 断言：`zh-CN` 与 `en` 的 key 集合完全相等、无空串、插值占位符一致；英文字典缺 key 时 `tsc` 直接失败。
3. 报告页至少一条主链路（画像 → 证据 → 分享）有中英双语快照测试或 E2E 断言。
4. 任一语言下缺失文案时渲染**可见的缺失标记**（如 `[missing: key]`）并让测试失败，绝不静默回落另一语言。

## 7. 已确认（随 W4/报告页落地）

- ✅ 报告页语言采用**路径段**：`/[locale]/report/...`（2026-09-11 W4 落地，利于分享与 SEO；与扩展无 URL 段的 localStorage/navigator 方案并存）。
- ✅ SSR 层注入 `lang`（Astro 布局）；hreflang 标注未做，列为非阻塞（如需要按 deferred 流程补）。

## 8. 浏览器扩展（apps/extension）落地（2026-09-14 增补，已实施）

扩展注入第三方 ATS 页面，**没有 URL 语言段、没有 SSR/Accept-Language 通道**，在沿用第 3 节契约（自研 `t()`、`{name}` 插值、`[missing:]` 可见标记、key 对齐测试）的前提下，语言来源与打包方式不同。

### 8.1 目录与运行时

- 扩展自建 `apps/extension/src/i18n/`（`messages/zh-CN.json` 单一事实源 + `messages/en.json` 同构 + `index.ts` + `i18n.test.ts`），结构与报告页一致，但**字典独立**：面板文案（表单、填充结果）与报告页文案不同，不共享字典、不跨端复用 key。
- i18n **运行时暂不抽共享包**：仅两个消费者且字典各自演化，复制这一份无 DOM 依赖的小运行时成本最低；**触发抽 `packages/i18n` 的条件**：出现第三个前端，或两端都需要复数/日期等复杂规则时。

### 8.2 语言检测与切换（无 URL 段场景）

1. 初始语言：先读 `localStorage['jobagent.locale']`（用户显式切换），缺省再按 `navigator.languages` 协商（`zh*` → `zh-CN`，其余回落 `en`，海外优先原则不变）。
2. 面板头部放语言切换按钮，点击写入 localStorage 并即时重渲染；切换按钮自身文案（English / 中文）是与报告页相同的硬编码豁免项，en 字典 CJK 守护测试对白名单 key 放行。
3. 悬浮球只显示品牌词 `JobAgent`（中英相同），避免「按钮 root / 面板 root」双 React root 间的语言同步问题。

### 8.3 MV3 元数据走 Chrome 原生 i18n（与面板 `t()` 是两套机制）

- `manifest.json` 的 `name` / `description` / `action.default_title` 是 Chrome 商店与工具栏文案，MV3 只认原生 `__MSG_*__` + `_locales/<locale>/messages.json` + `default_locale`，无法用自研 `t()`。
- 因此扩展同时维护 `_locales/en/messages.json` 与 `_locales/zh_CN/messages.json`（**Chrome locale 目录用下划线 `zh_CN`**，与自研字典的 `zh-CN` 命名不同，勿混），`default_locale: "en"`，`build.mjs` 把 `_locales/` 拷进 `dist/`。
- 面板内一切文案仍走自研 `t()`；两套字典不同源，但都要求中英齐备、同等质量。

### 8.4 不翻译边界（在扩展场景的具体化）

- ATS 页面自身文案、GitHub 原始内容（用户名、仓库名）不翻译，沿用第 5 节。
- `lib/api.ts` 抛出的 `analyze failed (HTTP n)` 等是**技术诊断信息**（同 CLI 内部工具，第 1 节非目标），保持英文、不进字典。
- 写入第三方申请表的 `summary` 前缀（原中文「技能（GitHub 验证，可回溯证据）：」）属于**扩展产出、招聘方可见的内容**，必须双语：纯函数 `toFillValues(profile, local, labels?)` 新增可选 `skillsLeadin/skillSeparator`，由面板用 `t()` 生成后注入，ats 层不依赖 i18n、默认值保持原行为以兼容既有单测。
- 真实性枚举沿用报告页术语：`likely_authentic → 可信度较高 / Likely authentic` 等四态，在扩展字典用 `auth.*` key 映射，不得直接把枚举原文抛给用户。
