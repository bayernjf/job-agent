- 状态：现行（2026-09-16）；**未启动实施，实施批次见 §5，进度记 handoff**
- 定位：针对 [市场调研-招聘市场痛点-20260916.md](市场调研-招聘市场痛点-20260916.md) 的 12 项痛点（企业端 6 + 求职者端 6）给出 JobAgent 解决方案、现状对位与实施批次拆分

- 日期：2026-09-16

## 1. 核心判断

12 项痛点中 **8 项的内核能力已落地**（真实性分级、技能提取、匹配、定向简历、双源融合），缺的是**把它们包装成 B/C 两端可见的价值入口**；真正新增只有 4 项（人才检索、筛选工作台、投递追踪、面试题导出）。JobAgent 的「可信行为证据」路线与双方痛点高度对位——共同解是"可信信号"：企业要可验证的履历（对抗 32.7% 造假率），求职者要可解释的匹配与反馈（对抗 75% 沉默淘汰）。

## 4. 共同根源 → 平台层对策

| 共同根源 | 平台级对策 |
| --- | --- |
| 信息不对称（根） | **单一可信画像 + 双向围绕同一证据对齐**——B 端看同一份证据、C 端用同一份证据投递（PRD 共享分析内核架构） |
| 平台两头收费（僵尸岗位+海投互放大） | **按验证价值收费**（背调/核验）而非"曝光+充值"两头吃；定价锚在"误聘成本 3 倍年薪" |

## 5. 实施批次拆分

### 批次 1（纯产品化，无新内核；把已覆盖项包装成价值入口）
1. **企业侧「核验视图」**：只看证据不看结论——报告页新增企业视角入口（真实性分级 + 证据外链 + 面试题），不依赖新接口。
2. **求职者「面试准备包」**：画像内嵌规则化面试题导出（md），复用现有面试题产出。
3. **「不刷题/可信证据」营销定位落地页文案**：落地页补双端价值主张。

### 批次 2（新接口/新存储，需新增后端能力）
1. **画像库人才检索（P-A）**：检索接口（技能标签/真实性分级/置信度过滤 + 排序）+ 企业侧只读视图；数据源为现有 profiles 快照，**不新增采集**。
2. **筛选工作台（P-B）**：候选人列表（排序/过滤/批量标记），复用人才检索接口。
3. **投递记录与反馈追踪**：新表 `applications`（画像侧投递动作 + 状态），报告页「我的投递」列表；企业侧反馈为远期（依赖账号体系）。

### 批次 3（依赖外部条件，缓做）
- 真实 LLM 润色（自配 `LLM_*` env）、服务端持久化与 PDF、账号体系后的完整投递闭环、跨端自动同步。

## 6. 验收标准（批次 1/2 通用）

- 每个新增入口：中英 i18n 双 key、`--ja-*` token 零 hex、就近单测 + 对应 E2E
- 检索/筛选：真实画像库抽样验证排序合理性；确定性夹具测试不打网络
- 投递追踪：新表双方言迁移（sqlite/postgres 对称 + down）、迁移校验 0 warning
- 全仓 `pnpm -r typecheck/test/build` 全绿、`git diff --check` 干净
