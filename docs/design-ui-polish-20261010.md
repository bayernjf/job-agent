# UI 定向升级方案（不推倒重来）

- 日期：2026-10-10
- 状态：方案（待拍板批次范围后落代码）
- 依据：生产三页面实测截图（首页 `/zh-CN/`、报告页 `/zh-CN/report/db772132…`、工作台 `/zh-CN/workbench`，2026-10-10 浏览器实拍）

## 1. 一句话结论

**当前 UI 的信息架构、证据链呈现与合规文案是强项；视觉层（宽屏栅格、品牌感、长页导航）偏素，值得一次「定向升级」而不是推翻重做。** 升级以扩展既有设计 token（`design-tokens-20260910.md` + `@jobagent/ui-tokens`）为手段，不引入新设计体系。

## 2. 实测问题清单（视觉层，非功能）

| # | 问题 | 实测依据 | 影响 |
|---|---|---|---|
| V1 | **宽屏内容列过窄**：1280 视口下内容仅占 x≈200~770（约 43%），右侧大片空白 | 三页面同款容器 | 桌面端显空、不专业；招聘产品吃信任感 |
| V2 | **视觉层级偏素**：白底黑字 + 文字框 badge，无主色/渐变/图标点缀；真实性分级靠文字区分 | 报告页「可信度较高 / 信号混合 / 证据不足」均为同款文字框 | 扫读时无法一眼抓到分级结论 |
| V3 | **报告页超长单列**：整页高约 4137px 一滚到底，无章节锚点导航 | torvalds 示例报告 | 招聘方查看长报告时找不到重点，增加跳失 |
| V4 | **工作台空态/加载态朴素**：偏好/任务/待投等空态均为单行文字；模块靠细线分隔 | 工作台四模块空态 | 首次进入引导感弱，不体现「Agent 产品」气质 |
| V5 | **响应式未知**：未在窄屏实测（本轮仅 1280 桌面视口） | — | 移动端为上市前待验项 |

> 注：2026-10-10 实测时工作台多处显示「正在加载求职工作台...」，复查确认是数据 fetch 中间态截图所致——全部数据接口（auth/me、preferences、runs、search、search-presets、llm-config、extension-tokens）均 200，**非功能缺陷**。本方案不包含功能修复项。

## 3. 升级原则（硬约束）

1. **不重做信息架构**：导航、分区、证据链（规则 ID 逐条可点）、授权分级闸全部保留。
2. **不改文案口径**：合规/诚实表述（「未经本人授权」「Agent 只准备、不投递」「AI 污染检测」等）一字不动；新增文案继续走 i18n 中英同构 key。
3. **基于 token 扩展而非推翻**：颜色/间距/圆角沿用 CSS 变量体系（`var(--tokens-*)`），新增品牌主色/状态色/层级 token，禁止散落 hex。
4. **不做装饰性动效**：只加「揭示状态/分层」的静态层级，不加无意义 hover 动画。
5. **双语言同步**：任何新增 UI 文案中英各一份，parity 守护保持绿。

## 4. 分批次落地建议

### P0 · 栅格 + 长页导航（约一个批次，收益最大、改动最小）
- **V1**：内容容器改宽屏栅格（1280 下内容列拉到 ~72% 并居中，`max-width` 与断点收进 token/工具类）；报告页、工作台、首页三处统一。
- **V3**：报告页加右侧章节锚点导航（概述/真实性/能力/证据/项目…），滚动高亮当前章节；长报告可快速跳转。断点低于 960 自动隐藏。

### P1 · 品牌视觉层级（第二个批次）
- **V2**：新增品牌主色 token（建议 1 主色 + 2 辅色 + 状态色集），报告页真实性分级用「颜色 + 图标 + 文字」三通道呈现（如 可信度高=绿✓ / 信号混合=琥珀△ / 证据不足=灰?），保留现有规则 ID 文本。
- 卡片层级：报告页证据卡、工作台模块卡统一阴影/圆角/边框 token；主按钮（生成画像/开始搜岗）用品牌色强化。

### P2 · 空态与引导（第三个批次，可选）
- **V4**：工作台四类空态（无偏好/无任务/无待投/无历史）补图标 + 下一步动作按钮（如「新建偏好」空态直接给入口）；报告页未认领横幅视觉强化。

### V5 · 响应式（随 P0 一起抽样验证）
- 窄屏（≤768）三页面走查一次，补齐明显溢出/挤压；不作为独立批次。

## 5. 明确不做（本期）

- 不换字体体系、不重做配色基调（白底深色文字保留）。
- 不做移动端 App / 桌面客户端。
- 不做引导页（onboarding tour）、不做插画体系。
- 不因 UI 改动触碰任何接口契约、数据模型与证据呈现逻辑。

## 6. 验收与时机

- **验收标准**：P0 落地后 1280 桌面视口三页面走查——内容列比例达标、报告页锚点可跳转、无回归（现有 report/workbench E2E 全绿）；i18n parity 空 diff；`git diff --check` 干净。
- **时机判断**：优先 P0（纯代码、低风险、无外部依赖）；P1/P2 可随后续功能批次插入。真实用户反馈（CWS 上架后试用）是 P1/P2 优先级的最终裁判——若试用反馈聚焦「看不懂证据」，P1 提前；若聚焦「找不到下一步」，P2 提前。

## 7. 决策点（需拍板）

| 项 | 选项 | 说明 |
|---|---|---|
| P0 是否启动 | 启动 / 缓做 | 纯代码低风险，建议启动 |
| 品牌主色基调 | 沿用现有绿/teal 系 / 换蓝系 | 现报告页/落地页已有绿-teal 渐变元素（Hero 卡片），沿用可保持一致性 |
