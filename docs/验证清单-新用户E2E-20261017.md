# 新用户视角功能验证清单（浏览器 E2E 实测）

> **定位**：以全新用户首次接触产品的视角，用真实浏览器逐项实测走通核心功能链路并核对预期表现；供 agent 操作浏览器做 E2E 时按项执行、留痕。核心主链路【核心】必验，重要功能【重要】按需验，平台健康【运维】顺手验。
> **入口**：https://app.job-agent.bayjf.com （2026-10-19 复测在线；`/api/health?deep=1` status ok、db ok、5 消费方心跳新鲜）。
> **执行方约定**：🟢自动＝agent 可自行在浏览器完成；🔵需用户＝需要真实账号 OAuth 授权、真人点击或外部动作。**验证停在产品边界**：不替用户提交表单、不进行真实投递、扩展填充后绝不点提交。
> **现状事实以仓库 [../handoff.md](../handoff.md) 与线上实测为准**；每次实测后在本文件「状态记录区」留痕（日期/覆盖/结果/发现），并同步 handoff 最近变更。

## 前置准备

- 浏览器：真实 Chromium（可访问 `app.job-agent.bayjf.com` 与 GitHub/Gitee OAuth 授权页）
- 账号：至少一个真实 GitHub 用户名用于生成画像（推荐用户本人，便于后续认领；匿名体验可用 demo 预置 torvalds/bayernjf/MSNightmare）
- 配额注意：未登录 demo 会话 3 次新分析/24h；同一用户名重复分析命中缓存、不计配额
- 已知边界见文末 H 节（Gitee OAuth 未冒烟、扩展 CWS 未上架、Workday 不支持、生产 LLM 未配时走规则版）

## A. 入口与登录

- ☑ 🟢 首页可访问：无需登录可见「输入用户名生成画像」，数据源三选一（GitHub / Gitee / GitHub+Gitee 融合）；页面含 How it works 与 Chrome extension 安装引导链接（2026-10-19 实测）
- ☑ 🟢 匿名体验：不登录也能提交用户名生成画像（demo 配额内）；「My profiles」可查进度与历史（2026-10-19 API 链路实测：裸匿名提交 403 `DEMO_REQUIRED` 显式化 → 建 demo session 后可提交（201 排队）；⚠ 页面级未登录交互待无痕复核）
- ☐ 🔵 GitHub OAuth 登录：授权弹窗 → 回跳同源 → 登录态持久（刷新不丢）；登录后可「认领」自己的画像
- ☐ 🔵 Gitee OAuth 登录：流程同 GitHub（⚠ 已知缺口：生产真实 Gitee App 凭证未冒烟，见 deferred #12；若失败先区分已知缺口 vs 新故障）
- ☑ 🟢 中英双语：报告页/工作台语言切换，两种语言 key 齐全、无英文硬编码漏出（2026-10-19 实测首页 /en/ 与报告 /en/report/... 同构）

## B. 【核心】能力画像生成（产品立身之本）

- ☑ 🟢 提交真实 GitHub 用户名 → 立即进入排队（异步，≤5 分钟被消费）→ 生成报告（2026-10-19：torvalds 排队 → job-8a8d9601 成功 → profile 71b24206-8f1c-41f8-9244-72398a28b727，引擎 0.1-0.9）
- ☑ 🟢 报告内容：真实性信号分级（L0 元数据 + L1 行为时序 + L3 语义洞察）、能力标签、证据链接（每结论挂 evidenceRefs）、分析时间窗与版本号（2026-10-19 实测：真实性 82% + 3 信号、语言/框架/领域标签带深度、REPO/COMMIT 证据、时间窗 2011-09-03 ~ 2026-10-19）
- ☑ 🟢 结论可回溯：点开任意证据引用能溯源到平台原始记录（2026-10-19 实测证据链接存在且 href 指向原平台；未逐条点击）
- ☑ 🟢 重复分析同一用户名 → 命中缓存快照：不重复排队/扣配额、结果完全一致（快照不可变）（2026-10-19 实测：torvalds 首跑完成后重复提交 → 秒级直接跳转报告，不排队）
- ☑ 🟢 数据源切换：同一用户名分别用 GitHub / Gitee / 融合 分析，报告标注对应来源与 caveat（2026-10-19 部分实测：匿名 **Gitee 源提交链路** 201（跨源失败路径）+ 画像来源标注 `subject.platform=github`；⚠ Gitee 成功路径 / 融合分析未测——无真实双源账号数据）
- ☑ 🟢 失败路径：不存在的用户名明确报 not_found；部分采集失败时报告**显式标注缺失层**，绝不输出"看似完整"的报告（2026-10-19 实测 not_found：worker L0 显式失败 `Could not resolve to a User with the login...`，UI 显示「分析失败/重试」；⚠ 部分采集失败降级路径未验）
- ☑ 🟢 配额路径：未登录连续触发**新分析**，会话第 4 次起明确报错（QUOTA_EXCEEDED）（2026-10-19 实测：demo 会话建会话→3 次新分析（remaining 2→1→0）→ 第 4 次 **429 `DEMO_QUOTA_EXCEEDED`**，resetAt +24h，完全符合设计）

## C. 【核心】报告与分享

- ☑ 🔵 面试题与 interview-kit 可查看/导出（需登录）（2026-10-19 已登录会话实测：interview-kit.md 下载成功，3352 字节）

## D. 【核心】求职 Agent 工作台（阶段 1 + 阶段 2）

- ☐ 🔵 设置求职偏好（目标岗位/技能/约束）→ 生成匹配条件
- ☐ 🔵 扫岗：从岗位池选出候选岗位，每条带**可解释匹配理由**（title/tag/description 匹配 + 缺口标签）
- ☐ 🔵 质量闸：被挡岗位显示原因（如 no_title_or_tag_hit），可**显式人工越过**（只放行质量闸；限频/确认/投递一道不少）
- ☐ 🔵 票据计划：选择岗位 → 生成任务，状态机推进 pending → approved → submitting → submitted → tracking（事件可回放、按时间升序）
- ☐ 🔵 投递限频：按岗位来源统计 24h 额度，超额**整批 429**、绝不部分确认
- ☐ 🔵 结果回写：投递结果反馈闭环；每封求职信末尾固定 AI 辅助披露、无法省略
- ☐ 🔵 扩展一键填充：unpacked 加载扩展 → 登录态授权 → 在真实 ATS（Greenhouse / Lever / Ashby）申请页一键填充简历/求职信 → **填完停手，绝不自动点提交**（Workday 不支持）
- ☑ 🟢 现状核对：生产有 **2 条 awaiting_approval** 真实待确认投递，工作台可见（2026-10-19 只读实测：任务 run-a478b801「待你确认/有新候选待确认」＋待投清单 Lemon.io「Senior React Full stack Developer」80k–200k USD/远程/待确认；事件流可回放：监控中→生成推荐中→待你确认；等待用户本人动作，决策 #20 永久边界）
