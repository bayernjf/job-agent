## 5. A5 部署 smoke 本地预演（含两个真实问题与处置）

以"生产等价"配置在本机跑 node standalone + `tools/smoke-deploy.sh`：

```bash
# 先用 storage CLI 预迁移一个 sqlite 文件（CLI 用位置参数，不读 DB_PATH）
pnpm --filter @jobagent/storage exec node dist/cli.js up /tmp/ja-smoke/smoke.db
# 生产等价启动（关键：DB_AUTO_MIGRATE=false，与形态 C runbook 一致）
DB_DRIVER=sqlite DB_PATH=/tmp/ja-smoke/smoke.db DB_AUTO_MIGRATE=false \
  CRON_SECRET=smoke-secret-123 PORT=4399 HOST=127.0.0.1 NODE_ENV=production \
  node apps/report/dist/server/entry.mjs
bash tools/smoke-deploy.sh http://127.0.0.1:4399 --cron-secret smoke-secret-123
```

结果：**自动项 7 passed / 0 failed**（health、根路径 locale 协商、/en/、cron 无 token 401、
cron 带 token 空队列 200、随机 job 404、demo presets 200）。

预演过程中发现并处置了两个真实问题：

1. **Node 大版本必须匹配（环境问题，非代码缺陷）**。
   shell 默认 node 是 v22，直接启动 standalone 会报
   `better_sqlite3.node NODE_MODULE_VERSION` 不匹配（原生模块按 Node 24 编译）。
   **处置**：启动前必须 `fnm use 24.0.0`；生产 Vercel runtime 已固定 nodejs24.x，不受影响。

2. **serverless cron 空队列时因缺 GITHUB_TOKEN 返回 500（真实代码顺序缺陷，已修复）**。
   `claimAndProcessOne` 在认领任务**之前**就构造证据源并校验 `GITHUB_TOKEN`，
   导致空窗期（队列本为空）也会抛 "GITHUB_TOKEN is not set" 并被路由转成 500，
   无法返回 `{kind:'idle'}`。生产环境配置了 token 不会触发，但空窗期每分钟刷 500 是错误行为。
   **处置**：将证据源构造（含 token 校验）延迟到"确认认领到任务、且非 demo 超闸退回"之后；
   常驻 `runWorker` 仍在启动时 fail-fast（语义不变）。新增守护单测
   "空队列 + 无 token + 不注入 source → idle"（worker 单测由 27 增至 28）。

3. **smoke 脚本根路径断言与设计不符（测试脚本缺陷，已修复）**。
   根 `/` 按设计无条件 302 协商到 `/en/` 或 `/zh-CN/`（`src/pages/index.astro`），
   脚本原误期望 200。**处置**：改为断言 `302` 且 `Location` 指向 `/en/` 或 `/zh-CN/`，
   本地化落地页 `/en/` 仍单独断言 200。

> 关于迁移目录：storage 用 `import.meta.url` 相对定位 `db/migrations/{sqlite,postgres}`，
> 在 monorepo 本地布局正确；被 Astro bundle 进 server chunks 后相对路径会错位。
> **形态 C 不受影响**——runbook 已规定 Vercel 设 `DB_AUTO_MIGRATE=false`
> （冷启动绝不碰 DDL，迁移只走 5432 直连流程，见执行单 B3/阶段 G）；
> 本单 smoke 也以 `DB_AUTO_MIGRATE=false` + 预迁移库验证了该生产路径。
