# 设计：职位聚合 Spike（P2 前置验证）

- 状态：现行（Spike 结论，P2 建库直接采用）
- 日期：2026-09-13
- 依据：决策 #16（2026-09-11 拍板"按原计划 P2 启动，当前只做准备"）；讨论记录-02 §4 职位聚合可行性
- 产出：数据源实测结论 + 最小链路建议 + `JobPosting` 类型（已落地 `packages/shared`）

## 1. 目标

验证"抓取 → 去重 → 存储 → 搜索"最小技术链路可行，确认数据源可得性/字段/频率/合规，P2 直接复用。**本轮只做验证与类型预留，不建采集服务。**

## 2. 数据源实测（2026-09-13 真实探测）

全部用 curl（经本机代理）实测，HTTP 码 / 体量 / 字段来自真实响应。

| 数据源 | 可达性 | 格式 | 字段覆盖 | 增量信号 | 合规/反爬 | 实现成本 |
|---|---|---|---|---|---|---|
| RemoteOK | ✅ 200 / 635KB | JSON 数组（首项为 meta） | 全：position/company/location/salary_min/max/date/tags/url/id/slug/verified | `last_updated` 时间戳 + 每条 `date` | ToS 要求"链接回源（follow）" | 极低（单 GET） |
| Remotive | ✅ 200 / 178KB | JSON（`{jobs:[...]}`） | 全：title/company_name/location/salary/url/publication_date/tags/category/description | 每条 `publication_date` | 公开 API（域名已迁 remotive.com） | 极低（单 GET） |
| We Work Remotely | ✅ 200 / 884KB | RSS（~89 条） | 少：title/link/pubDate/category；公司名嵌在 title，无独立字段 | `pubDate` | 官方 RSS | 低（XML 解析） |
| Greenhouse boards | ✅ 200（airtable token） | JSON（`{jobs:[...]}`） | 全：title/location/absolute_url/first_published/updated_at/requisition_id/metadata（content 需 `?content=true`） | `first_published`/`updated_at` | 官方公开 API，稳定 | 中（需维护 board token 清单） |

## 3. 结论：推荐组合与暂缓

**MVP 建库推荐（按优先级）**：

1. **RemoteOK + Remotive**（双公开 API 主源）——远程技术岗密集、字段全（含薪资/标签/描述）、单 GET 零维护、增量信号明确。覆盖面互补（RemoteOK 偏创业/营销，Remotive 偏远程全品类）。
2. **Greenhouse / Lever boards**（补充源）——覆盖大厂与中大型公司在招岗，官方 API 合规稳定；代价是需维护"board token / 公司 slug"清单（几百家即可覆盖大量岗位，P2 以公开聚合目录起步）。
3. **HN Who's Hiring**（长尾补充）——每月一次抓取，覆盖小公司/创业公司，自由文本解析成本中等，价值在长尾。

**暂缓/不做**：Wellfound（turnstile 反爬）、YC Jobs（406 + 内嵌数据）、WWR（字段太薄，仅作 RSS 备选）。国内源（Boss 直聘等）维持决策 #16 口径不接入。

## 4. 最小链路设计建议（P2 直接采用）

```text
抓取：每日 cron → 各源适配器（fetch → 解析 → 映射为 JobPosting）
去重：URL 唯一 —— jobs 表 UNIQUE(source, source_url)；跨源模糊去重用 (title+company+location 归一化) 哈希碰撞提醒
存储：复用 packages/storage，新增 jobs 表（迁移 NNN_create_jobs.sql，sqlite/postgres 各一份）；源字段存精简快照，不存 raw 全量（对齐 AGENTS 快照原则）
搜索：MVP 量级（万级行）SQL 过滤（title/company/tags LIKE + location/remote/salary 范围）足够；量级上来再评估 FTS
```

## 5. JobPosting 类型（已落地 packages/shared）

对齐现有 Zod 契约风格（schema + `z.infer`），字段以实测字段覆盖为准，`source`+`sourceUrl` 为去重唯一键。详见 `packages/shared/src/index.ts`。

## 6. 风险与开放项

- **去重键**：同源用 sourceUrl；跨源（同一岗位多家发）仅靠归一化碰撞提醒，P2 需确认是否做跨源合并。
- **board token / 公司清单来源**：Greenhouse/Lever 清单是持续维护成本，P2 定稿维护方式（公开目录抓取 vs 手工维护）。
- **频率**：建议 RemoteOK/Remotive 日更、GH/Lever 日更、HN 月度；实际增量以各自时间戳字段为准。
- **RemoteOK ToS**：对外展示需保留来源链接（follow），涉及报告页/落地页引用时注意。

## 7. 探测明细

- 2026-09-13，curl `-x http://127.0.0.1:7897`，各源真实 HTTP 码与体量见 §2 表。
- RemoteOK 首元素为 meta（含 `last_updated` 与 ToS 提示），职位从下标 1 开始。
- Greenhouse 示例 token `airtable`、Lever 示例 slug `alluxio` 均为公开 board，实测可达。
