- [x] **B2. 🖥️ 拿两条连接串**：Project Settings → Database → Connection string：
  - **Transaction pooler（6543）**——给 Vercel 函数，形如
    `postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres?pgbouncer=true&sslmode=require`
  - **Session pooler / 直连（5432）**——给迁移/Actions/CLI 预热。
  - 成功标志：两条串都在手；6543 串含 `pgbouncer=true`。（2026-09-27 完成）
- [x] **B3. 💻 本地跑首次迁移（用 5432 串，绝不拿 6543 跑 DDL）**（2026-09-27 完成）
  ```bash
  DB_DRIVER=postgres \
  DATABASE_URL='postgresql://...5432...?sslmode=no-verify' \
  pnpm migrate:pg:up
  ```
  成功标志：**14 个迁移（001–014）全部 applied**；再跑 `pnpm migrate:pg:status`（同样带两个环境变量）显示无 pending。
  **实际结果：14 个迁移全部 applied，`No pending migrations. Total: 14`，幂等重跑 no-op，exit 0。**
  **连接串必须用 `sslmode=no-verify`**：Supabase pooler 证书由 Supabase 私有 CA（`Supabase Intermediate 2021 CA`）签发，Node 内置信任库不包含该 CA，`sslmode=require` 会报 `self-signed certificate in certificate chain`（2026-09-27 实测，与网络/代理无关；已随 `feat(storage): support sslmode=no-verify` 支持该模式）。
- [ ] **B4. 🖥️ 开备份**：Database → Backups 确认自动备份开启（Pro 计划含 PITR；Free 仅有有限备份，上线前知悉）。**2026-09-27 用户拍板：暂用 Free（无自动备份），可手动 Create a backup 兜底一次；Pro 后续再开时启用自动备份 + PITR（记入 deferred/上线值守项）。**

> 失败处理：迁移连不上先查 5432 是否要求 IPv6（Supabase 直连在纯 IPv4 网络可能不通，Session pooler 5432 走 pooler 域名可通）；TLS 报 `self-signed certificate in certificate chain` 是 pooler 私有 CA 不被 Node 信任，**改用 `sslmode=no-verify`**（仅运维连接；6543 生产串在 Vercel 是否信任该 CA 需上线实测，失败同样改 no-verify）。

两种处置（部署时按平台真实行为二选一）：

1. 每次部署后在 Cron Jobs 面板重新核对/修正 path（运维动作，零代码）。
2. 若平台确以 vercel.json 为唯一事实源、手改必被覆盖，则把真实 `CRON_SECRET` 填入 `apps/report/vercel.json` 两条 path 后单独提交——**须知该 token 因此进入 Git 历史**：它只能触发「认领一个分析任务」与「清理过期数据」，不能读取任何画像/个人数据；上线后应把它视为**低密级调度令牌**，并在轮换流程中接受「轮换需改 vercel.json 并重新部署」。决策前先在 Vercel 当期文档确认 dashboard 编辑的持久化语义。
