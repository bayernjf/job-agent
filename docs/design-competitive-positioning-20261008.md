# 设计 · 竞争定位（JobAgent vs ChatGPT 帮投 vs Jobright）

- 状态：**现行（2026-10-08 新增，作为产品叙事与迭代锚点）**
- 一句话：**job-agent 的差异化不在"帮投"，在"证明"**——ChatGPT 赢在"写"，我们赢在"可核验"。
- 触发背景：用户问"ChatGPT 都能帮用户投递简历，我们的优势在哪、如何拉大趋势"。本设计回答这个问题，并把结论固化为对外叙事。
- 与既有文档关系：产品范围以 [PRD.md](PRD.md) 为准；求职 Agent 构想见 [设计-求职Agent-20261002.md](设计-求职Agent-20261002.md)；B 端方向见 [design-b-side-full-loop-20261007.md](design-b-side-full-loop-20261007.md)；Jobright 早期分析见 [讨论记录-02-投递功能与竞品分析-20260911.md](讨论记录-02-投递功能与竞品分析-20260911.md)。

## 0. 核心判断

通用 AI（ChatGPT 类）帮投简历的本质是：**用户说什么，它帮用户写什么**——生成能力强，但产物仍是"自我陈述"，招聘方无法核验。job-agent 的核心资产是**从 GitHub/Gitee 行为痕迹推导的可核验能力画像**：commit/PR/Issue/star 是客观痕迹，画像带真实性分级、证据引用（evidenceRefs）、逐条声明核验（claim verification）。**在招聘这个信任稀缺的场景里，可核验性就是护城河**——这不是生成能力能追上的，因为对手既没有行为数据源，也没有证据链基础设施。

## 1. 竞争格局定位图

| 玩家 | 内容可信度（自述 → 行为证据） | 求职自动化（单点工具 → 闭环 Agent） | 定位 |
| --- | --- | --- | --- |
| 传统简历工具 | 低（纯自述） | 低（单点生成） | 左下 |
| ChatGPT 帮投 | 低（生成强但不可核验、有幻觉风险） | 高（对话式生成+可触达外部系统） | 左上 |
| Jobright | 中（聚合+用户自填，无行为证据） | 高（800 万职位池+一键投递） | 右上偏中 |
| **job-agent（现在）** | **高（双源行为证据+真实性分级+claim 核验）** | 中高（匹配闭环+半自动投递，人机闸） | **右中** |
| **job-agent（目标）** | **保持高（证据轴继续做深）** | **高（闭环工作台+受控全自动边界）** | **右上角** |

要拉大的方向＝**两轴同时前进**：证据可信度继续做深（核验、证据链、B 端信任），自动化从"半自动投递"推向更完整的求职闭环——这一角是 ChatGPT 与 Jobright 都追不上的位置。

## 2. 差异化资产盘点（均已实现，可作证据）

| 资产 | 现状 | 对手可复制性 |
| --- | --- | --- |
| 双源行为证据画像（GitHub/Gitee） | L0 元数据 + L1 行为时序（含 events 多样性信号），真实性分级、evidenceRefs、规则版本化 | 低（需要采集体系+校准基线） |
| 逐条声明核验（claim verification） | 迁移 029 + `packages/claim-core`，简历声明可核验 | 低（需要证据链基础设施） |
| 画像↔岗位匹配可解释 | `MatchReport`（scoreTier + reasons + gaps + suggestedBoost） | 中（匹配易抄，可解释难） |
| no-fabrication 定向简历/求职信 | resume-core 每条断言挂 evidenceRefs，LLM 只改表达不引入事实 | 低（与证据链同源） |
| 半自动投递（人机闸） | 扩展一键填充 ATS，填完停手、绝不自动点提交（决策 #20） | 中（自动化易抄，信任设计难） |
| 求职工作台（Agent 闭环） | 偏好→扫岗→待投清单→确认→跟踪→复盘（状态机） | 中 |

## 3. 拉大差距的三个杠杆

### 杠杆 1：叙事转移——从"简历工具"到"能力证明层"

- 对外定位：**技术人才的能力证明层**（技术圈的 LinkedIn，但以代码证据为核心），不是"AI 简历生成器"。
- 与 LLM 的关系从"对抗"变"协作"：让 ChatGPT 类工具负责"生成"，我们负责"证明+匹配+投递闭环"。J7 生产配 `LLM_*` 后，润色进投递链（fail-closed 回落规则版），价值锚点仍在证据层。
- 效果：ChatGPT 无论生成多强，都无法自称"你的简历有行为证据背书"。

### 杠杆 2：数据飞轮——行为→技能→匹配的专有数据集

- 每分析一个账号，积累一条"行为→技能→岗位匹配"的真实映射；匹配引擎越用越准。
- 26 账号双源校准基线、规则版本化可回滚——这是对手拿不到的（无 GitHub/Gitee 证据体系）。
- 飞轮上游（更多候选人画像）靠 demo 模式与登录认领；下游（招聘方付费）见杠杆 3。

### 杠杆 3：B 端变现——招聘方为"核验+人才库"付费

- 候选人端免费引流；招聘方为核验、人才筛选付费（决策 #25 B 端分期，B1 人才库价值验证先行）。
- 招聘方付费意愿远强于候选人（为筛选效率买单），且 B 端核验不是 ChatGPT 的主战场。
- 合规红线不变：代传简历/全自动筛选不做（design-b-side-full-loop §合规红线）。

## 4. 对外定位声明（一话版本）

> **别人帮你"写"简历，我们帮你"证明"简历。**
> job-agent 把你的 GitHub/Gitee 行为痕迹变成可核验的能力画像，替你在技术岗位上持续找岗、评估匹配、备好定向简历，并在你确认后一键填充投递——每一步都可溯源，投递永远由你按下最后一下。

## 5. 迭代方向（由本定位推出的优先级提示）

- 短期（已具备）：半自动投递 + 工作台闭环 + 可解释匹配——把"证明+闭环"组合讲透。
- 中期（待拍板）：B 端核验入口（#25）、LLM 语义增强（J7/C1）、复盘反馈（样本≥20）。
- 不做：全自动点提交（阶段 3 明确不做）、非技术岗泛化（守住垂直纵深）。
